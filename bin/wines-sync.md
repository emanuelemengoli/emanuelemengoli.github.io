# Syncing the wine map from the tasting form

`_data/wines.yml` drives the map on `/le-mie-passioni/`. Instead of hand-editing it,
fill the **Scheda di degustazione del vino** Google Form after each tasting;
`bin/sync-wines` folds the responses into `_data/wines.yml` and you commit.

- **Merge / upsert** on *produttore + nome + annata*: each run adds new wines and updates
  matching ones (only the fields you filled). Entries the form doesn't mention are left
  untouched — you can delete old rows from the responses sheet whenever you like.
- Clicking a bottle shows a **compact summary**; if the wine has any detailed section
  filled (i.e. you chose *Completa*, or the *Corta* olfactory/taste pages), a
  **"Vedi valutazione completa"** button expands the popup.
- New wines are **geocoded** from `produttore, regione, stato` via OpenStreetMap
  Nominatim (cached in `bin/.wines_geocache.json`). If you fill **Latitudine** /
  **Longitudine** those win. A re-submission never moves an existing pin — change
  coordinates via those fields or by editing `_data/wines.yml`.

## The form

The form is generated by the Apps Script **`bin/analisi_vino/wine_tasting_form_generator.gs`**
(run `createWineTastingFormUXv11()` in [script.google.com](https://script.google.com)).
A plain-text walk-through of every question and the branching is in
**`bin/analisi_vino/form_model.txt`**.

Structure the script needs to know about (it matches on the exact question titles):

- **Identificazione** — `Cantina / produttore`, `Nome del vino`, `Denominazione`,
  `Territorio di produzione`, `Annata`, `Data`, `Prezzo` (numeric), `Regione`, `Stato`,
  optional `Latitudine` / `Longitudine`, and the **`Tipologia`** dropdown
  (Rosso / Bianco / Spumante / Rosé / Arancione → marker colour).
- A **`Valutazione`** dropdown per tipologia: **Corta** or **Completa**.
- The visual, olfactory and taste questions repeat once per tipologia branch and once per
  path, so the responses sheet has **many identically-named columns** — the script reads
  by position and takes the first non-blank one, so this is fine.
- Every aroma checkbox (the *Corta* macro-categories `🌸 Floreale / Fruttato` … and the
  *Completa* families `Floreale`, `Frutti rossi`, `Difetti`, `Evoluzione delle note
  fruttate nei vini rossi`, …) is merged into one `aromi` list; the `(esempi …)` suffix
  on the macro-category labels is stripped.

If you change a question **title** in the `.gs`, update the matching entry in
`FIELDS` / `AROMA_TITLES` at the top of `bin/sync-wines`.

## Publish the responses as CSV

The responses sheet:
<https://docs.google.com/spreadsheets/d/1POq8gMdiWmUW1XGcLe79nVkLSjUJk6UNqgsPl2Eq18E/edit>

1. In that spreadsheet: **File → Condividi → Pubblica sul web**.
2. Tab **Risposte del modulo 1**, format **Valori separati da virgola (.csv)**, **Pubblica**.
3. Copy the URL (ends `output=csv`) and save it once (git-ignored):

   ```sh
   echo "https://docs.google.com/…/pub?…&output=csv" > bin/wines_csv_url.txt
   ```

## Everyday use

The `Data` question is a Google Forms date item; in an Italian sheet it exports as
`GG/MM/AAAA`, so pass `WINES_DATE_ORDER=dmy`:

```sh
WINES_DATE_ORDER=dmy ruby bin/sync-wines
git diff _data/wines.yml
git add _data/wines.yml && git commit -m "wines: …" && git push
```

Flags: `--dry-run`, `--sort` (newest-tasted first), `--commit`.

## Notes & limits

- The responses sheet is the **input**, not a mirror — removing a row does not remove the
  wine from `_data/wines.yml`; delete it from the file.
- Match key is *producer + name + vintage*; re-submitting with any of them changed creates
  a new entry. A re-submission overwrites only the fields you filled; blanks keep the old
  value. Rename / clear a field by editing `_data/wines.yml`.
- First sync also tidies existing entries' formatting (a one-off). Per-entry `#` comments
  in the YAML aren't preserved; the header block is.
- Ruby's `csv` is bundled through Ruby 3.3; on Ruby ≥ 3.4 run `gem install csv` once.
